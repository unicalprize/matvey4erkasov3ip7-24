# Ретроспектива спринта №1

**Дата:** 07.10.2026
**Длительность спринта:** 1 неделя (1 занятие)

## Что прошло хорошо?
- Удалось за короткое время составить полноценный Product Backlog из 10 User Story с корректным распределением приоритетов (4/3/3).
- Разбивка историй на задачи по 1–2 часа позволила равномерно распределить работу и уложиться в 6 академических часов.
- Kanban-доска наглядно показала прогресс; WIP-лимит (≤ 2 задачи в In Progress) помог не распыляться.
- Все выбранные 5 историй спринта реализованы в срок.
- Git-история получилась чистой: 5+ коммитов с понятными сообщениями по ID задач.

## Что можно улучшить?
- Больше времени уделить тестам — не все функции покрыты unit-тестами.
- Раньше выявлять препятствия: вопрос по отсутствию `products.json` возник только в середине спринта.
- Улучшить формат коммитов — объединять связанные изменения, но не смешивать разные US в одном коммите.
- Проверять файлы на непустоту перед коммитом — была ситуация с `0 insertions`.

## Что попробуем в следующем спринте?
1. **Правило:** каждый коммит сопровождается ссылкой на US-ID и кратким описанием в теле коммита.
2. **Практика:** писать тесты до реализации функции (элементы TDD).
3. **Инструмент:** использовать GitHub Projects вместо локальной Markdown-доски для автоматического перемещения карточек.

## Конкретные улучшения на следующее занятие
1. Выделить первые 10 минут на уточнение требований с «заказчиком» (преподавателем) — какие функции приоритетны.
2. Завести отдельную ветку `sprint-2` в Git и вести работу только в ней, затем делать merge в `main`.
3. Ввести обязательный чек-лист перед перемещением задачи в Done:
   - [ ] функция реализована и работает на тестовых данных
   - [ ] написан хотя бы один unit-тест
   - [ ] сделан коммит с ID задачи
   - [ ] задача перемещена в колонку Done на Kanban
